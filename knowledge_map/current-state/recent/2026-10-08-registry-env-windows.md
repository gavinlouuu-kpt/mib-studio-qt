## 2026-10-08 — Profile registry env read from the OS environment on Windows (#571)

`AppBackend` read `MIB_PROFILE_REGISTRY_URL` and `MIB_PROFILE_REGISTRY_PUBLISHABLE_KEY` with `std::getenv`. On Windows the MSVC CRT snapshots the environment at process start, so a value the host sets later is invisible. That covers the Tauri shell and the bridge contract test, which uses Rust `std::env::set_var` → `SetEnvironmentVariable`. As a result `registry_commands_through_shell_transport` failed in the Windows Tauri candidate workflow. A local `processEnvironmentValue()` now reads through `GetEnvironmentVariableA` on Windows; it's the same approach as the bridge shim's `queueCapacityFromEnv`. On other platforms it uses `getenv`, so Linux behaviour is unchanged. See [[architecture/AppBackend]].
