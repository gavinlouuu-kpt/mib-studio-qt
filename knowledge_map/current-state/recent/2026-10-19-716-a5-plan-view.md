## 2026-10-19 — O3 Experiment · Plan in the opt-in workspace: a single-sample start with identity and annotation (#716 A5)

Step A5 of track A (#716), first PR, work package P4 (exec plan), on the reviewed Penpot board O3.
Desktop only; no bridge or contract change (it uses ABI 39, #712).

- **The Experiment stage opens on its Plan.** Sub-views Plan, Live and Summary; Live and Summary
  still say "Not yet in the workspace" and point to the classic view.
- **Sample format:** "Single sample"; "Sample queue" is shown inert with the reason "the guided
  queue comes in the next workspace step".
- **Sample sheet with the fixed schema of `/experiment_annotation`:** sample, condition,
  experimental unit, concentration (value + unit), channel, medium, temperature (°C), notes and
  free key/values; one colour per condition. The client checks every bound of the contract's
  `experiment_start_request` with the generated `EXPERIMENT_START_REQUEST` constants (bytes of
  UTF-8), refuses an over-bound value next to its field with the limit named, never truncates,
  and leaves an empty field out of the request (never `""`).
- **Identity:** `experiment_id` a lowercase UUID v4 minted when the plan is created
  (`getRandomValues`, so it also works on the instrument's plain-HTTP UI), `run_index` 1,
  `sample_ref` "S1", and the selected operator (name and optional id, remembered on this machine;
  recorded as "selected", not authentication). No calibration record id until A4.
- **Start run** runs the existing Start flow with the plan's `startRequestJson`, built by the pure
  `buildStartRequest`; nothing starts on navigation, and the classic Start sends no request. It is
  disabled with Prepare's own words while Prepare's checklist blocks (one verdict model), and for
  the classic Start button's reasons. The backend's `InvalidRequest` is shown next to the sheet in
  plain words with the plan kept; a started run locks the plan and "New plan" mints a new id.
- **Gate:** the navigation test now also visits the Plan, types in the sheet and switches
  sub-views (nothing that acts; only the path-less readiness read is added), and on a host that
  can start proves "Start run" sends exactly one `experiment_start` with the plan's text.
