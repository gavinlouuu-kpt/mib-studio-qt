## 2026-10-19 — Run snapshot v3: E-LUT identity, device readbacks, PL run id (#712)

The run snapshot on `/run_provenance` is schema 3 (additive to v2), so a recording says which
E-modulus LUT, pump settings and readbacks, LED strobe, stage and piezo it ran with. Start mints a UUID
v4 `run_id` (the FCS `$MIB_RUN_ID`), records the hash of the LUT bytes `ProcessingService` loaded beside
the catalog's labels (`catalog_matches_loaded` says whether they describe the same file; the hash is of the
bytes the table was built from, read once), the pump settings the pump is known to hold (written or read
back in this connection, `SyringePumpService::AppliedSettings`; never the configuration's defaults) and its
last complete poll (`SyringePumpService::runFacts`, at most 150 ms on the pump lock, so a pump busy with
serial I/O is written `connected: null`), the PZ7035 strobe registers
(`AppBackend::readInstrumentLed`), the stage driver's last status, the piezo voltage last read or
written, and the PL run id the host armed. Finalization adds `@run_stop_json` with the reason the backend
already had (`stop_requested`, `cancel_requested`, `fatal_save_error`, `shutdown`); no stop behaviour
changed. PL rows now store their FRAME record's `plRunId` / `plEpoch` per row (`ProviderFrame.runId` is
the record's, not the armed id). What a device did not report is `null` or absent and reads back as
`std::nullopt` (`recording::readRecordedRunProvenance`), including stage flags a readback omits; `""` is
never a value (written as `null`, read as unknown); v1/v2 files read every new member as unknown.
`writeRunSnapshotJson` refuses a read-only file and has a test fault seam. No bridge or contract change.
See [[data-model/HDF5-Storage]], [[services/Hdf5Service]], [[architecture/ExperimentCoordinator]],
[[services/SyringePumpService]]. Guards: `recording.run_provenance_record`, `backend.experiment_readiness`,
`backend.instrument_modes`, `backend.pl_science_provider`, `recording.experiment_roundtrip`,
`hdf_export_service`, the pump fake-serial tests.
