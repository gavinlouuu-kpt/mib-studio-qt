## 2026-10-11 — The Run frame rate is adjustable (bridge ABI 38)
Gavin: "The FPS should be adjustable." Run was fixed at 5 kHz / 150 us. Now `set_run_fps {fps, acknowledgeDiscardRing}` stores a whole number of frames per second from 100 to 5000 in the Aravis profile, `fetch_run_fps` reports the configured and applied rate, the derived exposure and the limits, and Studio's Run panel has a rate field (`RunRateControl`) that shows the exposure the rate implies.
- **Timing, option B:** HMAX 58 is forced in Run (`options.pzHmax`, the producer would pick 116 below about 2.66 kfps) and SHS stays 64, so the XVS-referenced LED strobe (delay <= 100 us, width <= 80 us) keeps straddling the exposure start; VMAX = floor(74.25 MHz / (58 x fps)) and the exposure is (VMAX - 64) lines: 5000 fps 150 us (unchanged), 1000 fps 950 us, 100 fps 9.95 ms. No PL, firmware or producer change.
- **Rules:** refused during an experiment or recording and while a stopped Run's ring is held unless acknowledged (the re-entry discards it); in Run the change re-enters Run at the same window; outside Run it applies at the next entry; the readiness gate fails if the camera runs at another rate than the configured one; the run snapshot records `run_timing`; the "5 kHz" texts follow the rate. The UI keeps "5,000 fps is the qualified rate; others are not yet validated on the board" until the 1 kHz slot passes.
- **Tests:** `backend.instrument_modes` (`testRunFps`), `runFps.test.ts`, `RunRateControl.test.tsx`, the contract test. Code: `include/backend/pz/PzRunTiming.h`, `AppBackend::setRunFps`, `BackendFacade::fetchRunFpsJson/setRunFps`, [[architecture/Rust-Bridge]] ABI 38.
