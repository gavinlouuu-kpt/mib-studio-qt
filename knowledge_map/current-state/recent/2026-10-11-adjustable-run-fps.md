## 2026-10-11 — The Run frame rate and exposure are set by a PZ7035 camera document (bridge ABI 38)
Gavin: "The FPS should be adjustable", set the way MIB Studio does it through its camera script. Config -> Camera document in YOFO Studio edits, saves and applies a PZ7035 camera document with the same editor as the camera scripts: `{"schema": "pz7035-camera/1", "run": {"frame_rate_hz": 1000..5000, "exposure_us": "auto" | number}}` (default 5000 / auto). `check_pz_camera_document` validates a text without side effects, `apply_pz_camera_document` stores it in the Aravis profile and re-enters Run when the instrument is in Run, `fetch_run_fps` reports the setting; the experiment page shows it read only.
- **Timing:** HMAX 58 is forced in Run (`options.pzHmax`; the producer would pick 116 below about 2.66 kfps). "auto" keeps SHS 64, so only VMAX grows when the rate falls and the exposure follows it: 5000 fps VMAX 256 / 150 us (unchanged), 1000 fps VMAX 1280 / 949.87 us (Gavin: "longer exposure"). A number is rounded to whole lines and must start the exposure inside the LED strobe pulse [7, 67] us (SHS 9 to 85). The strobe is the qualified 7/60 us and Service-only: the document refuses any strobe/LED/delay/width key. No PL, firmware or producer change.
- **Range:** 1000 to 5000 whole fps: the OCC LED driver strobes reliably only at about 1 kHz or faster (2 ms gap 54% of the light, 4 to 8 ms none).
- **Rules:** refused during an experiment/recording and, in a stopped Run, unless the discard of its buffered frames is acknowledged (outside Run nothing is discarded); the `instrument.mode` gate fails when the camera runs at another setting than configured; `instrument.strobe` proves the strobe overlaps the exposure (always for a valid setting); the run snapshot records `run_timing`; the "5 kHz" texts follow the rate; "5,000 fps is the qualified rate; others are not yet validated on the board." stays until the 1 kHz slot passes, which must also record the receiver line-error counters.
- **Review fixes:** a profile is a stored Run setting only with `experiment.hmax` 58, so the board unit's `MIB_ARAVIS_FPS=1000` seed never becomes the Run rate; the applied setting is stored before the mode becomes Run; `experiment.hmax` outside 58 to 65535 is ignored on load; the Run-entry staging (`pz::stageRunProfile`) and the producer's line period (`pz::producerHmax`) are unit-tested seams.
- **Tests:** `backend.instrument_modes` (`testRunTimingAndDocument`, `testRunFps`), `pzCameraDocument.test.tsx`, `runFps.test.ts`, `RunRateControl.test.tsx`, the contract test, `camera_document` Rust tests.
