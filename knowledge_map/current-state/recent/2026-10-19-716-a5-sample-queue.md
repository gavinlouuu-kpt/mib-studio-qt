## 2026-10-19 — The guided sample queue and the PZ7035 Run switch in Experiment · Plan (#716 A5)

Step A5 of track A (#716), second PR, work package P4 (exec plan), on the reviewed Penpot boards
O3, O4 and O5 (read at revn 218). Desktop only; no bridge, backend or contract change (it uses
ABI 39, #712, and the existing stop and status).

- **"Sample queue" is available** in the Plan's sample format. The sheet holds one row per sample,
  each with its own `sample_ref` (S1, S2, …) under the plan's one `experiment_id`, the same fixed
  schema and one colour per condition. Rows can be added at any time; reordered or removed only
  before they have started.
- **Guided, explicit at every step, over the existing commands only:** Start S1 (the classic Start
  flow with the row's start request) → Next sample (`experiment_stop`) → the drain and finalize
  followed in the polled experiment status, with progress → Confirm closed (the operator; sends
  nothing) → "Swap the tube for S2" → Start S2 (readiness with S2's file at its Start). Nothing
  advances, stops or starts on its own, and the shell holds no backend queue state.
- **Lifecycle stepper** (kit `Stepper`) for the current row, Planned → Starting → Running →
  Stopping → Finalized → Closed, with refused, unknown and failed steps in kit tones; the queue
  table shows each row's state, run index and output file.
- **Identity rules from #736:** each row's start reply alone decides started / refused / unknown;
  every Start sends the next run index, which only grows on started and unknown, so an index is
  never reused; started and unknown rows are locked and stay visible.
- **Failures stop the flow** with the reason and the operator's retry / skip / end choice (a
  refused Start, a lost start reply, a stop not accepted, a failed run).
- **A lost controlling client pauses the queue** (browser; `useHoldsControl`). It never resumes on
  its own: "Resume queue" needs control again and sends nothing; the backend's #711 safe stop still
  handles the instrument.
- **PZ7035 "Switch to Run":** the Plan offers the classic Experiment tab's entry switch as a button
  (the shared `applyCameraMode`) while the instrument is not in Run; Start stays disabled with the
  reason until then. Navigation still never switches modes.
- **Tests:** the pure queue machine (`queueModel.test.ts`), the view over the real controller
  (`QueuePlan.test.tsx`), and the whole App over the mocked transport (`navigation.test.tsx`: the
  queue's navigation sends nothing that acts; two samples send exactly start, stop, start, stop;
  the PZ7035 switch).

Not in this step: per-run auto-stop (a backend stop condition, its own ABI number), "base on
previous experiment", the queue preview, Live, Summary and Quick look. See
[[architecture/Desktop-Shell]] ("Opt-in workspace", Sample queue) and [[frontend/UI-Language-Kit]].
