## 2026-10-21 — Experiment · Live in the workspace (#716 A6b)

Step A6b of track A (#716), work package P4 (exec plan, "Keep the live inspection features…"), on the
reviewed Penpot board O4. The workspace's Experiment stage now has a Live sub-view
(`desktop/src/workspace/LiveView.tsx`, `liveModel.ts`, `useLiveCells.ts`, `liveImages.ts`) over the
live cell store of ABI 41 (A6a, [[services/MonitoringCellStore]]); no new bridge command.

- **What it shows**, laid out as O4: the live frame and the backend's detected-cell strip (kit
  `CellStrip` / `CellImage`, crops pulled as frame packets once per cell, at most two at a time, the
  mask only for the Mask overlay), the area–deformability scatter (kit `AreaDeformChart`, the
  classic chart's calibrated rows) with click-to-pin, the pinned cell with ◀ / ▶ and a modal viewer
  ("Open in window"), the run's file and counts, the sample queue's rows, and the run lifecycle (the
  queue's own, or the status-only Starting → Running → Stopping · drain → Finalized for any other
  run).
- **Pins** are sent only on a click and only by the controlling client; the reply's outcome is said
  in plain words (CaptureMismatch, LimitReached, …). Ended pins (a capture change) show their
  measurements and the reason, never an image, count toward the 16-pin cap, and "Clear ended pins"
  unpins them one by one; a control loss cancels that batch, which never resumes by itself. An
  identity of another capture or run is refused before anything is sent.
- **Separate stops.** "Stop & finalize run" stops one named run: the queue's own row through the
  queue (never while paused, never another run), or the run the status shows active by its
  `start_generation` (ABI 40). "Stop acquisition" is the classic Stop Camera and never runs under a
  run. "Freeze display" holds the frame, strip and scatter shown and sends nothing; a capture or
  run change drops the held strip and its crops even while frozen ("the capture changed").
- **Navigation.** Showing Live reads and turns monitoring on, as the classic Monitoring tab does
  (the visibility gate now includes the workspace's Live). Leaving it turns monitoring off only when
  no run is in progress: during a run it stays on until the run ends, so viewer clients keep their
  feed; the classic Monitoring tab follows the same rule, and only the controlling client sends the
  switch. The switch gates the monitoring rings only, never acquisition, recording or the run. A
  control loss pauses the queue in Live too; nothing resumes on its own.
- **Kit requests** on #715: point selection for `AreaDeformChart` (Live maps clicks through the kit's
  plot margins meanwhile, checked by a test against the kit's own rendering), a loading state and a
  custom missing text for `CellImage`, and a dialog.
