## 2026-10-09 — S1 of the SSD record (#667): a read-only SSD store, strip and run list (bridge ABI 35)

`SsdStore` (`include/backend/pz/SsdStore.h`) reads the SATA SSD through the board owner's `pzrec` CLI (pz7035 `tools/pzrec`, 6c948081) on a disk image: the state word
(R1), the open run's counters (R3) and the run table (R4, R5), parsed strictly from pzrec's JSON. A background thread refreshes it every second with a bounded
child process, so the bridge never waits for a slow drive; a non-zero exit, a timeout or JSON that does not parse is WEDGED with the stderr as the reason, never
READY. Bridge ABI 35 adds `fetch_ssd_status`, `fetch_ssd_runs` and a short `ssd` block in the instrument status; the experiment readiness has an informational
`storage.ssd` gate (the experiment does not record to the SSD yet). The UI (`ssdView.ts`, `SsdStrip`, `SsdRunsPanel`) shows the storage strip and a read-only
Recordings list when an SSD is configured (`MIB_PZREC` + `MIB_SSD_IMAGE`), and a "No SSD: nothing can be saved" line in Diagnostics otherwise. A run recovered at
mount (reason 7) shows "Recovered after power loss: true totals unknown" and no numbers. No register offsets are used; start/stop, export and delete are S2 and S3.
"Recovered after power loss" comes from the run table, not from pzrec's one-shot status fields (coordinator ruling): any entry with reason 7 shows the badge for as long as it exists, and the notice after a Studio restart names the reason-7 runs whose id is above the highest run id Studio had seen before (kept in `ssd-state.json` in the data dir on the eMMC, written atomically).
The run being recorded is not in the table the UI reads (pzrec does not read it while recording): its row takes the numbers from the live status.
Review hardening (#680): the child-process runner waits on the child's exit under a deadline (a child that closes its pipes and keeps running, or a grandchild that
holds them, can no longer hang the refresher or shutdown); the store is created in `initialize()` so the state file path is never lost to an early status read; a run
table with duplicate ids or `end_lba < start_lba` is refused whole; a run whose totals do not add up (seen = empty + invalid not sampled + passed, passed = written +
dropped + failed) shows "—" and "Totals inconsistent: numbers not shown" (`totals_inconsistent`); the state file is written durably (fsync, rename, fsync of the directory).
Size is still shown for reason-7 rows (it is the LBA span of the entry, not a count).
