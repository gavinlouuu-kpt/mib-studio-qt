## 2026-10-09 — Saved files carry the right date on the board (#651 G14)

The PZ7035 has no RTC and no NTP, so a file saved on it carried the date the board booted with (May 2025 on the 2026-10-09 slot).
The controlling browser now sends its `Date.now()` (`sync_wall_clock {unixMs}`, controller only) when it becomes the controller and every
10 minutes. `backend::app::WallClock` keeps the offset to the monotonic clock, so a later system-clock change cannot move a run;
times outside 2026 to 2100 are refused, a change under 2 s is jitter, and the clock is kept while an experiment or recording is
active. Experiment start and end and the raw recording's start and end are stamped from it, and the file records
`timestamp_wall_source` (`client_sync`, `board_clock_unsynced` for a board no client has synced, `system_clock` on a host) and
`timestamp_wall_offset_ns` next to the other `timestamp_*` provenance; the run snapshot JSON has the same two fields.
With no sync the run is **marked, not blocked**: the Experiment readiness shows a non-blocking `clock.wall` warning, so
unattended runs still start. `fetch_instrument_status` gains `wall_clock{synced, source, offset_ns, last_sync_unix_ms}` (additive).
The SSD run table's start time (#667) uses the same source. See [[HDF5-Storage]].
