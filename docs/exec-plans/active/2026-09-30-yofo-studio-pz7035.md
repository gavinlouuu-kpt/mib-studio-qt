# YOFO Studio on the PZ7035: PL science, headless PS backend, remote React UI

Status: proposed, 2026-09-30. Decision: [ADR 0008](../../decisions/0008-yofo-studio-pl-instrument.md).
Board-side counterpart: pz7035-imx426 `docs/decisions/0002-*.md` and
`docs/processing/MIB_PARITY_PORT.md` (the PL porting list lives there; this plan links to it).

## Authorization and scope

Gavin decided on 2026-09-30: migrate to React + Tauri, no LCD for now, web React for
testing, rebrand this version to YOFO Studio, all real-time and time-sensitive operation in
the PL, the PS consumes only preview images under time pressure. This plan turns that into
work packages. Nothing here authorises hardware actuation beyond the bench rules in
pz7035-imx426 `docs/PZ7035_OPERATIONS.md` (LED driver off before reprogramming).

## System

```
PL                                                 PS (Linux, YOFO Studio backend)
IMX426 -> receiver -> classical profile 1          /dev/pz_mib0 records (FRAME/RESULT/EVENT)
  mask -> CCL -> metrics -> E-mod LUT -> gates       -> PL execution provider (E3)
  -> target decision -> timed sort output            -> accounting, monitoring, trigger status,
  -> RESULT/EVENT records ---DMA ring--------->         autofocus metric, HDF5 metadata
  -> preview slots -----DMA----------------------> GenTL producer -> Aravis -> AravisCamera
  -> store filter -> frame store -> SSD               (LatestFrame, tens of fps) -> live view
config/arm/stop  <--- ioctl SET_CONFIG/CONTROL <--- ExperimentCoordinator + config compiler
sensor/strobe    <--- GenICam features         <--- CameraControlService
                                                   Rust bridge server (WebSocket) -> React app
                                                   in a browser / Tauri shell on the network
```

## What leaves the PS (per-frame functions and their PL disposition)

Source of truth for the host behaviour: `src/backend/processing/ProcessingService.cpp`
(`realtimeInlineLoop`, 2516-3100), `BundledProcessingKernel.cpp`, `ProcessingScience.cpp`.
The PL implementation status per row is in the board repository's port list.

| # | Host function today | PL disposition | Host change |
|---|---|---|---|
| 1 | ROI crop (`makeGrayROI`) | ROI in profile parameters | config compiler emits ROI |
| 2 | Gaussian blur, odd `gaussian_blur_size` | exists (3x3 fixed); parameterise | none |
| 3 | Saturating subtract of blurred background, threshold | exists; threshold as parameter | none |
| 4 | Cross morphology close x n, open x n | exists (1 iteration); parameterise kernel and iterations | none |
| 5 | Empty check: nonzero count **before** morphology < `empty_frame_pixel_threshold` | new counter; FRAME flag EMPTY | provider reads flag |
| 6 | Auto-background (30 empty + 1000 cooldown) and calibrated background (mean of 10) | **stays on PS** from preview frames; PL gets a background write path and bank swap at SOF | background computed from `AravisCamera` frames; upload via provider |
| 7 | `findContours(RETR_TREE)`; objects = inner contours (holes); fallback to outer when allowed; area < 10 px dropped; bbox order | CCL with hole ownership exists (SIM); throughput and `require_single_inner_contour` are gaps | none |
| 8 | Per-object metrics: parent bbox/centroid, hull area/perimeter, area ratio, deformability, ring ratio, brightness quantiles, border touch (2 px) | aggregate + metrics engine exist (SIM, combinational); pipeline for 7-series; gray alignment gap; border margin | provider decodes RESULT payload into `FilterResult` |
| 9 | E-modulus: bilinear over 200x200 IDW grid indexed by (area um2, deformability); NaN out of coverage | loadable LUT in BRAM + pipelined bilinear; OUT_OF_COVERAGE flag | provider uploads the grid built by `EModulusLut` |
| 10 | Gates: area um2, ring ratio (15,25), deformability, area ratio; `isValid`; invalid reason | new gate block; reason code in RESULT flags | config compiler emits gate words |
| 11 | Target group: valid and area and deformability and optional E range | new; drives `res_target` | config compiler |
| 12 | Trigger: first valid target per frame, one pulse, `pulseDurationUs`; unserved targets counted | PL timed output (exists for class/score; needs target flag, delay, width); EVENT record; UNSERVED counter | `TriggerService` becomes configuration + status only |
| 13 | Recording selection: trigger-anchored valid frames, every 100th invalid, multi-image N following | PL store filter | HDF5 assembled after the run |
| 14 | Accounting and funnel counters | PL counters exposed in FRAME flags/status; reasons per RESULT | provider sums records (`accounting_*` stays the truth) |
| 15 | Monitoring rows, fps, reason histogram | from records on the PS | provider fills the existing rings |
| 16 | Tracking (batch/review only today) | not ported | unchanged |
| 17 | Autofocus: median ring ratio, 50 ms loop | not ported; metric from records | `AutofocusService` takes its samples from the provider |
| 18 | Contract 2 (absdiff, preprocessing chain, Laplacian variance) | later profile | none in this plan |

Time-insensitive functions that stay on the PS unchanged: experiment lifecycle and readiness,
config validation, profiles, LUT catalog, review, reanalysis and export (host science on
stored images), pump, nanopositioner, discovery.

## Work packages

### W1 Decision records and manifests
- [ ] ADR 0008 accepted; pz7035 ADR 0002 accepted.
- [ ] E0 manifest edits listed in ADR 0008 Consequences; renumber the E0 ADR; run
      `scripts/check_embedded_target.py`.
- [ ] pz7035 manifest edits (display class, capability rows, topology node) and
      `scripts/check_platform_manifest.py` green.

### W2 Platform (board repository, pz7035-linux)
- [ ] Live bitstream rebuilt with the full vendor PS7 configuration (DDR, UART0 MIO,
      USB, SD) so one `ps7_init` serves firmware and Linux.
- [ ] SD/QSPI boot with FSBL loading the bitstream (also removes the LED-on-at-power-up hazard).
- [ ] Yocto image: UIO nodes for the register window and preview RAM, reserved DMA memory,
      Aravis 0.9 recipe, MIB runtime dependencies (OpenCV core/imgproc/imgcodecs, HDF5,
      SQLite3, OpenSSL, spdlog), sshd, debug tools.
- Gate: cold boot from SD to SSH with the camera streaming; evidence in pz7035-linux docs.

### W3 ARMv7 build of the backend (E1 #445)
- [ ] CMake toolchain file and preset for the Yocto SDK sysroot; `MIB_BUILD_BACKEND_ONLY`.
- [ ] Native processing cores gain a `linux_armv7` name (the bundled kernel is still needed
      for review/reanalysis on the PS).
- [ ] `FrameStore` capacity from the target manifest (preview ring, tens of frames).
- [ ] Measured RSS and idle CPU of the backend on the board.
- Gate: `backend.lifecycle_smoke` and `integration.e2e_headless_experiment_smoke` pass on the
  board with the mock camera.

### W4 Aravis spike, then producer (board repository owns the producer)
- [ ] Spike: a fixed-pattern GenTL producer (`.cti`) on the PS, `arv-tool` and
      `arv-camera-test` through Aravis 0.9's GenTL consumer. Go/no-go for Aravis; the fallback
      is a native `PzCamera` backend on the driver interface, with the `.cti` kept for
      third-party tools.
- [ ] Producer over UIO on the existing grabber, serving `pz7035_sfnc.xml` (exposure, frame
      rate, strobe, lane order, GT reset, open/close ported from `live_server.c`).
- [ ] `AravisCamera`: device selection by id, `LatestFrame`, timestamps from chunk data,
      commit the WIP from `feat/aravis-framework`.
- Gate: YOFO Studio backend on the PS shows live frames through `CaptureService` at >= 25 fps
  with the strobe synced.

### W5 PL execution provider (E3 #447)
- [ ] `IExecutionProvider` seam next to `ProcessingService`: start/stop, config commit,
      record consumer thread, `FilterResult` decode for profile 1, accounting, trigger status,
      funnel, autofocus samples.
- [ ] Config compiler: `ProcessingConfig` -> ROI, blur, threshold, morphology, empty threshold,
      gate words, target-group words, `p2m`, LUT grid upload, background upload. Needs pz7035
      ABI 1.2 (parameter page).
- [ ] Fake/replay provider from ABI fixtures for tests without hardware (E0 rule).
- [ ] Readiness gates gain `provider.capability` (profile id/version, parameter page size).
- Gate: replay of the ABI fixtures reproduces the host kernel's `FilterResult` rows on the
  conformance set (D1-D6 in the board repository).

### W6 Recording on the instrument
- [ ] Store policy words from the config (valid-anchored, every Nth invalid, multi-image N).
- [ ] Post-run HDF5 assembly: metadata from live records, images and masks from the store
      drain; same layout as `Hdf5Service`; `software` attribute "YOFO Studio <version>".
      The drain/convert runs in C++ on the PS (Python is not in the ARM runtime allowlist).
- Gate: a run's HDF5 opens in review on the desktop with counts equal to `accounting_*`.

### W7 Remote React UI
- [ ] Rust bridge server on the PS: `mib-bridge` + WebSocket, existing bridge contract,
      binary frame packets, serves the React build as static files.
- [ ] Frontend transport switch (Tauri IPC | WebSocket); client-loss -> controlled Stop & Save.
- [ ] Rebrand: `tauri.conf.json` productName/title/identifier, `desktop/package.json`,
      installer names, update feed, `index.html`, `App.tsx` title.
- Gate: browser on the bench PC operates a full experiment on the board.

### W8 Bridge DMA and driver (board repository)
- [ ] `pz_mib_bridge` in the live image; kernel driver for `/dev/pz_mib0` (UAPI v1 + STORE ioctls).
- [ ] Producer moves from UIO grabber to preview slots; provider moves from polling to the ring.
- Gate: 5000 fps run with 0 record loss and preview at >= 25 fps, measured.

Order: W1 -> W2 -> (W3, W4 spike in parallel) -> W5 (against fixtures) -> W6, W7 -> W8. The
PL science port (board repository) runs in parallel from W1 and gates W5's hardware evidence.
