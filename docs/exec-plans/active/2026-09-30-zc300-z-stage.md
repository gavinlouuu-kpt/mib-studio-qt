# ZC300 Z stage integration

Status: active

Issue: [#464](https://github.com/gavinlouuu-kpt/mib-studio-qt/issues/464) · ADR: [0013 — Motorized stages are a separate device class](../../decisions/0013-motion-stage-device-class.md) ·
Evidence: [ZC300 + TBZF6-60 integration](../../integration/zc300-z-stage.md) ·
Baseline: `e1c2bf3` on `develop`

## Goal

MIB Studio can discover, connect to, and safely drive a Zolix ZC300
controller with a TBZF6-60 Z stage from the Tauri shell, on Linux, on
Windows, and later on the PZ7035. All user-facing and API units are
micrometres. Stage state is recorded as
provenance in every recording. A stage-driven Z sweep produces µm-labelled
focus data for the focus benchmark (#423) and the cells-different-focus
corpus. Autofocus behaviour is unchanged.

## Scope

In scope:

- The `IMotionStage` interface and the `backend::stage` module.
- The ZC300 protocol library, driver and `zc300ctl` CLI.
- Function code 0x04 in the shared Modbus layer.
- `StageService`, the discovery provider, facade commands and operations, and
  the bridge contract.
- The Tauri stage panel.
- Operator-initiated Home: probe both limits, define mid-travel as 0 µm.
  The reference holds once per controller power-up.
- Recording provenance, plus a Z-sweep acquisition operation.
- Hardware-gated acceptance on the bench unit.
- The PZ7035 manifest entry.

Not in scope, each tracked separately:

- Autofocus using the stage (a follow-up ADR, informed by sweep data).
- Multi-axis XY stages; the interface allows them, but no driver is written.
- The PZ7035 kernel, device-tree and bitstream changes that enable USB serial
  (pz7035-imx426).
- Changing the controller's DIP-switch current (bench hardware task).
- Any Qt UI. The Qt shell gets no stage tab: it is being retired under
  ADR 0001, and the stage is reachable only through the facade and Tauri.

## Global constraints

- **Qt-free backend.** Public stage headers contain no `QObject` and no
  vendor handles. `stage_zc300_protocol` depends only on the C++17 standard
  library and `ModbusRtu.h`.
- **Safety invariants (ADR 0013 §5)** are asserted by tests, not only
  documented:
  - Discovery and connect write nothing.
  - Nothing moves at start-up: with the default `reference.on_startup:
    false`, start-up issues zero motion and zero writes. Discovery,
    reconnect, config reload and recording start never move the stage.
  - Before Home has succeeded for this power-up, only Home and Stop are
    accepted.
  - Every move target passes the soft-limit check before any byte is written.
  - Motion opcodes are sent at most once per request.
  - Disconnect, shutdown, cancel and missed deadlines issue an immediate stop.
- **Threading.** One status-poll thread per connected stage. All bus I/O goes
  through `ModbusBusSession::transact` (the bus mutex is innermost). The
  realtime and processing threads never touch the stage. The code passes
  TSan and has a stress test with a watchdog.
- **Bridge.** Changes are additive only (ADR 0004): append-only enums, one ABI
  bump, and parity between the C++ static_asserts, the Rust contract test
  and the generated TypeScript.
- **HDF5.** New attributes and datasets are optional. Legacy files and
  stage-less runs read as "no Z information". The schema change needs
  round-trip and fault-injection tests.
- **Housekeeping.** Vault notes are updated in the same PR as the code, and
  `scripts/check_docs.py` must pass. Logging uses spdlog only.

## API contract (settled in slice 2)

The headers are the source of truth: `include/backend/stage/StageTypes.h`,
`StageProfiles.h` and `IMotionStage.h`. The shape is summarized below.

```cpp
namespace backend::stage {

enum class StageKind { Zc300 };                      // append-only
enum class AxisKind { Linear, Rotary };
enum class Direction { Negative, Positive };
enum class MoveState { Idle, Moving, Homing, Faulted };
enum class StageError {
    None, NotConnected, WrongDevice, Misconfigured, Busy, OutOfSoftLimits,
    LimitSwitch, EmergencyStop, DriverAlarm, NotEnabled, NotReferenced,
    OffGrid, InvalidArgument, Timeout, LostAck, Protocol, Transport,
};

struct StageEndpoint { std::string systemPort, usbSerial; std::uint8_t modbusAddress{1}; int axis{0}; };
struct StageIdentity { std::string model, serial, firmware; };   // "ZC300-1A", "26017", "1.2"
struct StageStatus {
    MoveState state; double positionUm;
    bool referenced;                                 // StageService fills it; drivers report false
    bool limitPositive, limitNegative, home, emergencyStop, driverAlarm;
    std::int64_t sampledAtNs;
};
struct AxisCalibration { AxisKind kind; double umPerPulse; double commandQuantumUm{1.0}; };
struct StageProfile { std::string name; AxisKind kind; double leadMm; std::int32_t pulsesPerRev; double travelUm; };
StageProfile tbzf6_60Profile();                      // 0.7 mm, 1600 pp/rev, 6000 µm

class IMotionStage {
public:
    virtual StageError connect(const StageEndpoint&, const StageProfile&, StageIdentity&,
                               std::string& detail) = 0; // observe-only; mismatch -> !isConfigured()
    virtual void disconnect() = 0;                   // stops first only if moving
    virtual bool isConnected() const = 0;
    virtual bool isConfigured() const = 0;
    virtual AxisCalibration calibration() const = 0;
    virtual StageError readStatus(StageStatus&) = 0;
    virtual StageError moveAbsolute(double targetUm) = 0;   // returns once accepted
    virtual StageError moveRelative(double deltaUm) = 0;
    virtual StageError jog(Direction) = 0;           // continuous until stop() or a limit
    virtual StageError stop() = 0;                   // immediate, idempotent, retried
    virtual StageError setPosition(double um) = 0;   // redefine the coordinate; no motion
    virtual StageError setSpeed(double umPerS, double umPerS2) = 0;
    virtual StageError applyProfile(const StageProfile&) = 0; // the only config write; saves to flash
    virtual StageError readPowerUpToken(std::uint16_t&) = 0;   // volatile 30054 (ADR 0013 §6)
    virtual StageError writePowerUpToken(std::uint16_t) = 0;
};

std::unique_ptr<IMotionStage> createStage(StageKind, services::serialbus::SerialBusManager&);
}
```

### Units: micrometres

- **Everything above the driver is in µm.** That covers the API, config
  keys, bridge DTOs, the Tauri panel, HDF5 attributes and sweep parameters.
  No mm, pulses or volts are exposed for the stage.
- **Commands are in whole micrometres.**
  - The ZC300 runs in **mm unit mode**, the only mode that gives µm command
    granularity. Distances go on the wire as `round(um) / 1000 + 1e-5` mm,
    which defeats the controller's 0.001 mm truncation and float32 loss.
  - A target that is not a whole number of micrometres is rejected with
    `OffGrid`, never silently rounded. Sweep steps must also be whole
    micrometres.
- **Readback is finer than 1 µm.** The controller counts pulses (0.4375 µm),
  so a 100 µm target reads back as 100.19 µm. `positionUm` reports that value
  unrounded. The panel shows one decimal; recordings store the commanded
  target and the read-back position separately.
- **The controller is checked at connect, without writing.** Connect verifies
  that the unit is mm, the stage type is linear, and the lead and pulses/rev
  match the configured stage profile (TBZF6-60: 0.7 mm, 1600). On a
  mismatch, the connection stays up read-only, status reports
  `Misconfigured`, and all motion is refused.
  - Fixing it is an explicit action, `zc300ctl configure --profile
    tbzf6-60 --allow-write` or the facade command `ApplyStageProfile`. It
    writes those four registers and then saves them to flash.

`StageService` (the `backend::services` API used by the facade; settled in
slice 3, `include/backend/services/StageService.h`):

- **Connection:** `setConfig(StageConfig)`, which is refused while connected.
  Then `startup()`: read-only, and it connects only when `enabled`. Also
  `connect()` / `disconnect()`, and `snapshot()`, a value copy published by
  the worker. The snapshot holds the connected/configured/referenced flags,
  identity, status, span, soft limits, the active operation and the last
  error.
- **Motion:** `moveTo(um)`, `moveBy(um)` and `reference()` (Home) each return a
  `StartResult`: an operation id, or an error. `stop()` is always allowed;
  there are also `cancel(id)`, `operation(id)` and `waitForOperation(id,
  timeout)`.
  - Operations end in exactly one state of `Completed`, `Failed`,
    `Cancelled` and `TimedOut`.
  - The approach direction, overshoot and deadline come from config. There is
    no per-call options struct yet.
- **`applyProfile()`** is the only controller-configuration write.
- **Config:** `parseStageConfig(json)` validates the `stage` block of
  `config.json`. Wiring it into profile apply and the facade is slice 4.

  ```json
  "stage": {
    "enabled": false,
    "endpoint": {"usb_serial": "A10RB8XC", "port": "", "address": 1, "axis": 0},
    "profile": "tbzf6-60",
    "reference": {
      "on_startup": false,
      "search_speed_um_s": 1000.0,
      "expected_span_um": 6000.0, "span_tolerance_um": 300.0,
      "search_margin_um": 500.0,
      "soft_limit_margin_um": 100.0,
      "power_up_token_register": 30054
    },
    "require_reference": true,
    "max_unreferenced_jog_um": 0.0,
    "approach": {"direction": "positive", "overshoot_um": 20.0},
    "speed_um_s": 1000.0, "accel_um_s2": 2000.0,
    "poll_ms": {"moving": 50, "idle": 500},
    "move_timeout_margin": 2.0
  }
  ```

The soft limits are derived, not configured: ±(measured span/2 −
`soft_limit_margin_um`), which is ±2900 µm for a nominal TBZF6-60. While
unreferenced, and while `require_reference` is true, only `reference()` (Home)
and `stop()` are accepted. A rig may allow small relative jogs before Home by
raising `max_unreferenced_jog_um` from its default of 0.

### Referencing: mid-travel home

`StageService::reference()` runs as operation `StageReference` when an
operator presses **Home**; the panel asks for confirmation first. It requires
the stage to be uniquely identified, the profile to match, and no e-stop or
alarm.

Start-up is read-only by default (decided by Gavin on 2026-10-05). The
`StartupDiscoveryCoordinator` runs referencing automatically only if a rig
explicitly sets `reference.on_startup: true`. The steps are:

1. **Negative limit.** At the slow search speed, make a controller-bounded
   relative move of at most `expected_span + search_margin` (6500 µm) toward
   the switch. Never an open-ended jog: the controller enforces the bound
   even if the host stalls, and the ZC300 stops early at a tripped switch.
   Fail if the move ends without the X− bit (30015 bit 1) set. Record
   `p_neg`. If the stage already sits on the switch, record the position
   directly.
2. **Positive limit.** Search positive the same way and record `p_pos`.
3. **Span check.** Check that |`p_pos − p_neg` − `expected_span`| ≤
   `span_tolerance`. Otherwise abort: the wiring is wrong, the stage slipped,
   or the profile is wrong.
4. **Midpoint.** Move absolutely to the midpoint `(p_neg + p_pos)/2` with the
   configured one-sided approach.
5. **Zero.** `setPosition(0)` (register 30059..60, no motion). Record the span
   and the time. From here on the stage is referenced and the soft limits are
   active.
6. **Power-up token.** Write a random non-zero token to the volatile register
   `power_up_token_register` (30054), and persist {controller serial, token,
   span} in application state.

**On connect:** if the stored serial and token match the controller, the stage
is referenced. The controller has not been power-cycled since Home, and its
position counter (including any front-panel moves) is still in the
referenced frame. A token of 0 or a mismatch means the controller was
power-cycled or something else touched the register; the stage is then
unreferenced and the stored token is discarded. If hardware acceptance finds
that 30054 does not behave as a volatile scratch register, the token is
disabled (`power_up_token_register: 0`) and the reference is held for the
application session only.

Any failure, cancel, e-stop, alarm or step deadline issues an immediate stop,
leaves the stage **unreferenced**, and reports `Failed` or `Cancelled` with
the step and reason. Nominal duration is about 15 s at 1 mm/s (6 + 6 + 3 mm).
The controller's own home opcode (`0x69`) and the TBZF6-60 home sensor are
not used. The home-sensor bit may be logged as a consistency check.

## Wire-level rules (from the evidence doc)

| Rule | Where it is enforced | Test |
|---|---|---|
| Registers 30001–49 are FC 04, 30050+ are FC 03 | protocol lib | `zc300_protocol_test` |
| Motion opcodes use FC 10 and are never retried; a lost ack triggers a status/position read to decide whether the move started | driver | fake bench: drop the ack, assert one opcode on the wire and a `LostAck` or accepted result |
| Reads and idempotent writes are retried up to 3 times after silence | driver | fake bench: drop one reply after move end |
| A jog toward an active limit is refused with exception 07; the limit bit stops a jog | driver | fake bench: limit asserted at a scripted pulse count |
| Writing 30059..60 redefines the position without motion (not yet verified on hardware) | driver | fake bench + hardware acceptance |
| Save (`0x6D`) waits 3 s for its ack | driver | fake bench: 1.1 s delayed ack |
| Distances go on the wire as `round(um)/1000 + 1e-5` mm; non-integer µm targets are rejected with `OffGrid` | protocol lib and service | table test using the observed pulse counts |
| Connect reads the unit, stage type, lead and pulses/rev; a mismatch with the profile gives `Misconfigured` and refuses motion, with no write | driver | fake bench: pp-mode controller; assert zero writes and a refused move |
| Absolute moves put the target in 30114 and its sign in P/N | protocol lib and driver | frame golden test |
| Exception 06/07/08/09 map to `Busy`/`LimitSwitch`/`EmergencyStop`/`NotEnabled` | protocol lib | table test |
| Status bits 30015 decode to limits, home, e-stop and alarm | protocol lib | table test |

## Acceptance criteria

- [ ] `ModbusRtu.h` frames, predicts and correlates FC 04. The existing
      `modbus_rtu`, `serial_bus_pty`, pump and pulse-generator tests are
      unchanged and green.
- [ ] `stage_zc300_protocol` and `stage_zc300` build on Linux, Windows and
      the ARM toolchain. `zc300ctl info|status` works read-only; `move`,
      `home` and `save` refuse to run without `--allow-motion`.
- [ ] A fake ZC300 slave (`tests/support/fake_zc300.h`, pty and
      `SerialPortFactory`) reproduces every row of the wire-level rules
      table, and each row has a test.
- [ ] Referencing tests pass against the fake stage:
  - Nominal: zero lands at the midpoint and the soft limits become ±2900 µm.
  - Starting on either limit.
  - A span outside tolerance.
  - A limit that never trips (the search distance is exceeded).
  - E-stop or alarm during a step.
  - Cancel during each step.
  - With the default config, start-up issues zero motion opcodes and zero
    writes. With `on_startup: true` it is still skipped when identity is
    ambiguous or the profile mismatches.
  - Power-up token: a matching token on reconnect gives a referenced stage; a
    token of 0 (power-cycled), a mismatched token, or a different controller
    serial gives an unreferenced stage. Before Home, everything except Home
    and Stop is refused.
  - Every failure path leaves the stage stopped and unreferenced.
- [ ] `StageService` safety tests pass:
  - Instrumented fakes see zero writes during discovery, connect, reconnect,
    config reload and default start-up.
  - Out-of-limit targets never reach the wire.
  - Stop wins over an in-flight move, cancel and shutdown.
  - A missed move deadline stops the stage and reports `TimedOut`.
  - Unreferenced motion is bounded.
- [ ] A concurrency stress test runs repeated move, stop, poll, disconnect
      and shutdown cycles with a watchdog and `_Exit(99)`. It passes the TSan
      lane.
- [ ] The discovery provider identifies a ZC300 by model string and serial
      read over FC 04, never by VID/PID alone. It returns a `Persistent`
      identity `zc300:<serial>` with the USB iSerial for port re-resolution.
      It never scans more than the requested port and addresses.
- [ ] The facade, bridge and Tauri path is complete:
  - `StageCommand` connect, disconnect, move to/by, home, stop, settings and
    `ApplyStageProfile` (the only command that writes controller configuration).
  - Operation kinds `StageMove`, `StageReference` and `ZSweep`.
  - Discovery kind `MotionStage`.
  - Contract parity passes: static_asserts, `cargo test` contract and
    `gen_bridge_contract.py --check`.
- [ ] Tauri stage panel (commissioning page), with vitest coverage of its state
      handling:
  - Connect and identity display.
  - Live position with a referenced badge.
  - Limit, e-stop and alarm indicators.
  - Jog ±step, go to, home (with confirmation) and stop.
  - Stop stays reachable and enabled whenever the stage is connected.
- [ ] Recording provenance:
  - `/recording_info` and `/experiment_info` carry the stage identity, Z
    start/end in µm, the referenced flag and the calibration.
  - Round-trip and fault-injection tests pass.
  - Legacy files read as "no Z".
- [ ] Z sweep:
  - The `ZSweep` operation takes start, stop, step, frames per step, settle
    time and approach direction.
  - It records frames with per-frame `z_um` and a sweep index.
  - It is cancellable and stops the stage on cancel.
  - A pipeline e2e test runs it with the mock camera and the fake stage.
- [ ] Hardware acceptance on the bench unit is recorded in the evidence doc
      (opt-in `MIB_TEST_STAGE_PORT` and `MIB_TEST_STAGE_ALLOW_MOTION=1`):
  - Identity and status reads.
  - A ±0.1 mm move, and an absolute return that is pulse-exact.
  - Stop during a continuous move.
  - **Before Home is used unsupervised:** a supervised, slow jog to each
    limit, confirming the switch polarity, the X−/X+ mapping and the
    measured span (about 6000 µm).
  - `reference()` ends at mid-travel. Its span stays within tolerance across
    10 runs, and the midpoint is repeatable within 5 µm.
  - A cold application start: no motion, and the stage is reported
    unreferenced.
  - After Home, an application restart keeps the reference. After a
    controller power cycle, it is reported unreferenced.
  - Register 30054 is writable, keeps its value across disconnects, clears
    at power-up, and is untouched by front-panel use. If not, the plan falls
    back to a per-session reference.
  - Limit-switch refusal.
  - E-stop refusal, if the controller has an e-stop input wired.
  - 20 one-sided approaches to a fixed target, with spread checked against
    the ≤ 2.5 µm repeatability rating using an independent measurement:
    focus metric or dial gauge.
- [ ] The PZ7035 target manifest (#441 branch) lists "Z stage (ZC300
      Modbus RTU)" as not required for standalone, with evidence
      `compilation` and the endpoint unknown. The USB-serial kernel
      prerequisite is cross-linked to a pz7035-imx426 issue. Referencing is
      operator-initiated, so the E0 rule "boot must never start motion"
      (ADR 0012, per ADR 0011) holds unchanged.
- [ ] Vault notes (`StageService`, `ZC300`, updates to SerialBus and
      DeviceDiscovery), the task note, `Recent-Work` and the ADR index all
      land, and `check_docs.py` passes.

   - `include/backend/stage/{IMotionStage,StageTypes}.h`.

   - The fake slave, and protocol and pty tests.
   - The ADR moves to accepted.
3. **`StageService` and `AppBackend` wiring.** Config block, poll thread,
   operations, shutdown ordering (stop the stage before releasing the bus,
   after the discovery drain), and the safety and stress tests.
4. **Discovery provider and facade/bridge.** The `ZC300Provider`,
   `DeviceKind::MotionStage`, `StageCommand`, the new operation kinds, the
   ABI bump, and the Rust and TypeScript mirrors.
5. **UI.** A stage panel on the Tauri commissioning page
   (`desktop/src/stage.ts` plus its component and vitest tests). There is no
   Qt work.
6. **Recording provenance.** Hdf5 attributes, per-frame `z_um`
   (`RecordingFrameMeta` plus the processed-frame metadata), and the
   round-trip, fault-injection and legacy-read tests.
7. **Z sweep.** The `ZSweep` operation, pipeline e2e, and a
   `scripts/run_focus_sweep.py` hook for #423.
8. **Hardware acceptance and PZ7035 manifest.** Bench results go in the
   evidence doc; the manifest entry and cross-repo issue are added.
   - **A per-controller "limits verified" record.** A guided, supervised
     procedure sets it: a slow jog to each limit with Gavin present,
     confirming polarity, mapping and span. Home refuses until it exists.
     Reason: the 6500 µm search bound exceeds the ~6000 µm travel, so
     unwired switches would let a search reach the hard stop.

Slices 1–3 are the minimum useful stack: headless control with a CLI.
Slices 4–5 make the stage usable from the app, and slices 6–7 are the
scientific payoff.

## Open questions

1. **Physical placement.** Which rig does the stage sit on, and does it carry
   the piezo (coarse and fine stacked) or replace it? Home sweeps the full

## Decision log

- 2026-10-06 (slice 4, coordinator + Gavin's safety rules):
  - **No start-up/auto-Home on the bridge:** `stage_connect` is
    observe-only, and `reference.on_startup` stays backend-only.
  - **Stop:** `stage_stop` is always accepted (no experiment lock) and is not
    a server `CONTROL` command.
  - **Experiment lock:** every other stage command is refused unless the
    experiment is idle. Motion is queued under the coordinator lock; connect
    and disconnect only check it.
  - **Moved forward from slice 8:** the limits-verified gate, because slice
    4 is the first to expose Home outside the backend. It is a per-serial
    record written only by `zc300ctl verify-limits --supervised`, after an
    operator-paced, stepped (≤ 500 µm) and bounded check.

- 2026-10-06 (fix after slice 3): the Home limit search is a
  controller-bounded relative move (opcode 0x65) at the slow search speed.
  - Previously it was an open-ended jog that the host stopped by polling.
    Windows CI showed it overshooting the 6500 µm bound by ~300 µm, through
    sleep granularity; any host stall on real hardware would do the same.
  - Host polling now only detects the end, and can stop earlier, never later.
  - `search_speed_um_s` is capped at 2000 µm/s.
  - The bound fixes timing, not unwired switches: it is larger than the
    travel. The "limits verified" gate is planned for slice 8.

- 2026-10-05 (slice 3): One worker thread owns the driver and runs connect,
  disconnect, operations and idle polling. `stop()` is the only cross-thread
  driver call.
  - A **stop epoch** (bumped after each `stop()` reaches the driver) cancels
    any operation that started before it. The stress test found a Stop issued
    between operations stopping the next move; without the epoch that move
    failed as "stopped short" and dropped the reference.
- 2026-10-05 (slice 3): Home uses jog-to-limit (opcode 0x66) plus
  `setPosition`, never the vendor home opcode.
  - Failures that can desync the open-loop counter drop the reference: limit
    switch, e-stop, alarm, lost ack, timeout, transport or protocol error.
  - An operator Stop keeps the reference.
  - New error `ReferenceFailed`: span out of tolerance, or a limit not found.
- 2026-10-05 (slice 3): `parseStageConfig()` lands now. Applying it from
  `config.json` and profiles goes with the facade in slice 4, so slice 3 adds
  no bridge or ABI change.
  - `mib_backend` now links `stage_zc300`, so `crates/mib-bridge/build.rs`
    names the two stage archives (link order only, not the ABI).

- 2026-10-05 (slice 2): `SerialBus.cpp` moves from `mib_backend` into the
  existing `oeabt_serial` archive, which already holds the platform
  `ISerialPort`.
  - `zc300ctl` then links `stage_zc300` without the whole backend.
  - The Rust bridge's hard-coded archive list (`crates/mib-bridge/build.rs`)
    and the bridge ABI stay untouched.
  - A new `mib_serial_bus` archive would have needed a `build.rs` change.
- 2026-10-05 (slice 2): `IMotionStage::connect` takes the `StageProfile` and
  returns `StageError`.
  - New errors: `WrongDevice` (the model is not a ZC300) and
    `InvalidArgument`.
  - New primitives: `applyProfile`, `jog`, `setPosition` and the power-up
    token.
  - Home stays out of the driver and the CLI; it is `StageService`'s
    referencing (slice 3).

- 2026-09-30: The stage is a separate device class, not a widened
  nanopositioner (ADR 0013).
- 2026-09-30: The library is in-repo CMake targets (the OEABT pattern), not a
