# MIB Studio v1.2.0 — 2026-10-08

## Highlights

- **FCS 3.1 export for FlowJo.** Review ▸ **Export FCS…** writes a FlowJo-compatible `.fcs` file for the open run. **Batch Export FCS…** converts many runs at once (#520, #574).
- **Safer experiment files.** Pressing Record during a run can no longer damage the experiment file. Background and ROI changes are locked while a run is active. The run's saved and dropped frame totals are written correctly to the file. Stopping a multi-image run keeps the last, partly filled series (#451, #542, #544, #546, #582, #403).
- **Clearer run outcomes.** A run that lost frames or hit a save error is classified as such. Review and the end-of-run message no longer report it as complete. After a save error (for example a full disk), acknowledge the fault to return to idle; no restart is needed (#549, #584, #589).
- **Monitoring density.** Experiment ▸ Monitoring can colour the scatter plot by density (KDE) and draw a live core contour. The contour is stored with the run and shown again in Review.
- **What's New and an offline user manual** under Help. The update prompt now shows what changed before you install (#573).

## Added

- **Review ▸ Export FCS… / Batch Export FCS…** (#520, #574)
  - Writes FCS 3.1 with the run's calibration. An `_event_map.csv` beside each file maps every FCS event back to its frame.
  - Existing files are never overwritten: choose a new name.
  - The buttons are disabled for raw recordings, which have no detections.
- **Review ▸ Charts**
  - Zoom with the mouse wheel and pan by dragging; reset the zoom from the right-click menu.
  - Click a point to open that cell's frame.
- **Experiment ▸ Monitoring ▸ Density (KDE)**
  - Density colouring of the live scatter plot and a live core contour, with Core %.
  - A reference contour under Settings ▸ Monitoring Settings….
  - Contours stored in the run file and shown in Review ▸ Charts. Right-click there to compute the core contour from the full run.
- **Review ▸ Metrics:** a **Young's modulus (kPa)** column at the end of the metrics table and the metrics CSV. It is blank where no modulus is available. Existing columns are unchanged (#230).
- **Readiness checks before a run:**
  - A test write to the destination folder.
  - A check that one full image series fits the recording memory budget.
  - Both are shown with the other checks before Start (#403).
- **Multi-image series timing:** every frame in a multi-image series is stored with its frame index and camera/host timestamps. A series with a missing frame is flagged as gapped instead of being saved as if consecutive.
- **Overview ▸ Wafer Grid:** detects the dot-grid fiducial pattern on supported chips, identifies the chip design, and overlays the grid on the live image.
- **Illuminated Live View:** the "Camera trigger & strobe (MindVision)" settings run live view with the LED strobe synchronised to the camera. Stopping live view also stops the strobe.
- **Device discovery:**
  - The Connect tab finds cameras, the nanopositioner and the pulse generator in the background at startup.
  - Devices are released cleanly on exit.
  - A second copy of the app can no longer start and fight over the hardware.
- **Help ▸ What's New** (these notes, shown once after each upgrade) and **Help ▸ User Manual**. Both work without an internet connection (#573).
- The **update prompt and Settings ▸ Software Updates** show the release notes of the offered version (#573).
- The installer can now install the **MindVision Camera SDK 2.1.10.195** (optional task), as well as eGrabber.

## Changed

- Live processing no longer uses OpenCV's internal thread pool. This removes frame loss seen in experiments at 5000 fps.
- Large frames trigger the periodic save to disk sooner, keeping memory bounded during long runs (#407).
- **New HDF5 chunk layout:** run files store one frame per chunk. This removes the slowdown seen when saving long multi-image runs (#226). Older run files remain readable, and the new files open in earlier readers.

## Fixed

- **Record during an experiment:**
  - Record is refused while an experiment is running.
  - Before, it closed the experiment file mid-run: the run's frames went into the recording, and the experiment file came out incomplete (#451).
- Background and ROI changes could be applied in the middle of a run. They are now refused until the run ends, and the Clear ROI, Set Background, Auto background and Calibrate buttons are disabled with a tooltip that says why (#542, #582).
- The saved and dropped frame totals in the experiment file header did not match the run (#544, #546).
- A frame that the camera delivered damaged was not counted as a loss, so a run could be reported as complete when it was not (#549).
- Exported Review charts had red and blue swapped (#467).
- Review did not show the run outcome (complete, incomplete, failed) for experiment files (#584).
- **Processing profiles** (#583):
  - After switching profiles, Monitoring ▸ Apply reported a false "configuration file changed" conflict.
  - After deleting the active profile, saved changes did not reach live processing.
  - Renaming a profile did not update its name in the list.
  - The "update available" banner stayed after updating a profile.
- Saving a `config.json` with Windows line endings failed with "the document changed on disk since it was loaded" (#590).
- After a fatal save error, the app stayed in the Failed state until restarted, and the run file recorded the run as intentionally partial instead of failed (#589).
- Stopping a multi-image run discarded the series that was still filling (#403).
- The app could crash on exit while the Nanopositioner tab was receiving status updates (#405).
- Saving the nanopositioner settings could replace the configured initial autofocus voltage with the voltage read back from the device, for example 0 V.
- The installer checked the 32-bit system folder for the Visual C++ runtime, so the runtime could be reported as installed when it wasn't.
- Stopping Illuminated Live View could leave the LED lit (#413).
- Closing the app while devices were still being discovered could crash it (#431).

## Removed

- The unused YOLO segmentation service and its ONNX Runtime dependency (#565). No feature in the app used it. Cell detection runs in the processing core and, on the YOFO instrument, in the FPGA. The installer is smaller, and the `yolo11n-seg` model and ONNX Runtime DLLs are no longer installed.

## Known issues

- **Don't record into an NTFS-compressed folder.** At 1000 fps the disk can't keep up: the save queue fills in about 13 s and frames are lost. Use an uncompressed folder (in Windows Explorer: Properties ▸ Advanced ▸ clear "Compress contents to save disk space").
- A run file that is missing one of its accounting attributes is read as zero frames instead of being flagged as unreadable (#570).
- FCS export is not yet available in the React/Tauri preview app, which is not part of this release.

## Hardware & compatibility

- Windows 10/11 x64.
- **eGrabber SDK 25.10.0.57** (Euresys Coaxlink; tick "Install eGrabber SDK" in the installer if it isn't already installed).
- **MindVision Camera SDK 2.1.10.195** (optional installer task).
- Microsoft Visual C++ 2015–2022 Redistributable (x64), installed by the full installer.
- Run files written by v1.2.0 open in v1.2.0 Review and YOFO Review. Older run files remain readable.

## Upgrade notes

- Install with `MIB_Studio_Qt_Setup_v1.2.0.exe` over v1.1.x. Settings, profiles and calibration are kept. The update package (`MIB_Studio_Qt_Update_v1.2.0.exe`) is for PCs that already have the camera SDKs.
- What's New opens once after the upgrade. Help ▸ What's New shows it again at any time.
- If you used `MIB_DISABLED_SERVICES=yolo`, it is still accepted and has no effect.
