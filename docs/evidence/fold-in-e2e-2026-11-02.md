panics, and the test exits non-zero.

## Evidence classes

- **Mock camera.** The folder camera (`data/mock_frames`, one 512x96 frame looped) and its
  fake GenApi node map (`evidence: fixture/mock`). It is never hardware.
- **Real backend.** Native authorities on real files: the coordinator, the recorder/HDF5,
  F's evaluator, the recipe provider and the SQLite workspace store, in a real server
  process.
- **Synthetic data.** The mock runs recorded and reconciled. Their frames hold no accepted
  cells: 0 processed and 0 objects, with every admitted frame scientifically rejected. So
  steps F04 to F09(A/B) use recordings written by the production `Hdf5Service` writer
  (`review_fixture_write_population`, 6,000 cells, seeds 11 and 12). The ≥3-units comparison
  and the 4PL fit use generated FCS 3.0 files, read by the native FCS reader (8 units and
  21 units).

## Notes

- Before the runs, E02's refusal under realtime processing and the refusal while an
  experiment is active were both asserted.
- I02: the recipe diff against the instrument reports `method: different` with the reason
  "The applied configuration was changed after local profile e2e-method was applied". The
  backend is correct here. The profile authority applies a method only with realtime
  processing off, and re-enabling realtime processing for the runs (`apply_processing`)
  counts as a configuration change. A user cannot apply a method and then run it without
  the diff marking it changed. This is worth a product decision.
- E01 after the restart: the old feature token was refused as `stale` on read and on write
  (readback null). The old discovery job was refused with `stale: true, job_id "0"`, and its
  cancel returned false.
