# AI Experiment Supervisor — offline evaluation and opt-in live JEV test

Issue #422, ADR [0006](../decisions/0006-ai-experiment-supervisor.md).
The supervisor is a **shadow-mode** recommendation layer: it never actuates
anything. This guide covers (1) the deterministic, network-free evaluation
that CI runs, (2) the opt-in live JEV evaluation, and (3) enabling shadow
mode beside a real experiment.

## 1. Offline evaluation (CI, no network)

Fixtures: `tests/supervisor/*.json` — one labelled decision point per file
(`case_schema` 1, `dataset_version`, `expected` answers, frozen `snapshot`).
They are generated by `tools/supervisor_gen_fixtures.py`; edit the scenario
table there, regenerate, review the diff, bump `DATASET_VERSION` when a label
or input changes. The label must never appear inside `snapshot` (the loader
rejects it).

Build the backend tests and run the rule baseline:

```bash
cmake --preset linux-backend-only && cmake --build --preset linux-backend-only-build
ctest --preset linux-backend-only-test -R supervisor --output-on-failure
```

or the tool directly (JSON + text reports):

```bash
build/linux-backend/Release/supervisor_eval_run \
    --fixtures tests/supervisor --provider rule \
    --out supervisor-eval-rule.json --text supervisor-eval-rule.txt --fail-on-unsafe
```

Options: `--calibration 0.5,0.6,0.7,0.8,0.9` (thresholds for
`P(correct | selected probability ≥ t)` and `P(correct | confidence ≥ t)`),
`--min-frames N` / `--loss-limit F` (policy limits), `--fail-on-unsafe`
(exit 5 when any false STOP / false CONTINUE occurs).

The report covers: agreement per question with confusion matrices; false
STOP (expected CONTINUE/ADJUST, got STOP_*), false CONTINUE (expected
STOP_*/HUMAN_REVIEW, got CONTINUE/ADJUST); adjustment target/direction
agreement; HUMAN_REVIEW rate; latency p50/p95/max; provider failure rate;
cost when the provider reports it; calibration buckets; every disagreement
with its `decided_by`. Cases the deterministic policy decides (`expect_policy`
in the fixture) are reported as `policy` and never count as model accuracy.

## 2. Opt-in live JEV evaluation

Never run in normal CI. Requirements:

| Variable | Meaning |
|---|---|
| `MIB_JEV_ENDPOINT` | HTTPS URL of the JEV decision endpoint |
| `MIB_JEV_MODEL` | **pinned** model identifier; a response naming another model is rejected (`modelMismatch`) |
| `MIB_JEV_API_KEY` | credential (or set `MIB_JEV_API_KEY_ENV` to the name of another variable) |
| `MIB_JEV_TIMEOUT_MS` | optional, default 10000 |

The credential is read at call time, sent only as `Authorization: Bearer …`,
and never written to results, records, logs or error text. Do not commit it.

```bash
export MIB_JEV_ENDPOINT=https://jev.example/v1/decide
export MIB_JEV_MODEL=jev-2026-09-01
export MIB_JEV_API_KEY=...   # from your secret store
build/linux-backend/Release/supervisor_eval_run --fixtures tests/supervisor \
    --provider jev --out supervisor-eval-jev.json --text supervisor-eval-jev.txt
```

`supervisor_eval_run` links libcurl when CMake finds it (the Linux
backend-only preset does); the backend library itself has no HTTP client
(ADR 0002). Without libcurl the tool exits 4 and says so.

Request/response contract (adapter `jev-adapter/1`, decision contract 1):
the request carries `contract_version`, `model`, the closed token lists per
question, and the canonical snapshot; the response must be a JSON object
with `answers` (one token per question), optional `distributions`
(`question -> {token: p∈[0,1]}`), optional `confidence ∈ [0,1]`, optional
`rationale` (display only, truncated), optional `cost_usd`, optional `model`
(must equal the pinned one). Unknown tokens, extra questions, out-of-range
probabilities or non-JSON bodies yield a typed error and the fail-closed
`HUMAN_REVIEW` answers. 401/403 are not retried; timeouts, 429 and 5xx are
retried once (bounded by the policy's `providerMaxRetries`).

Compare the JEV report with the rule report on the same `dataset_version`
and contract version; treat threshold selection as the empirical result the
calibration table gives, not as a safety guarantee.

## 3. Shadow mode beside a real experiment

Disabled by default. Enable at boot:

```bash
MIB_SUPERVISOR_MODE=shadow \
MIB_SUPERVISOR_PROVIDER=rule        # or jev (needs the variables above + a shell HTTP transport)
MIB_SUPERVISOR_INTERVAL_MS=5000     # decision cadence, ≥ 500
MIB_SUPERVISOR_OBJECTIVE="collect 500 valid cells"
MIB_SUPERVISOR_TARGET_VALID=500     # deterministic completion rule
./mib_studio_qt
```

While an experiment is Active the service freezes a snapshot every interval,
evaluates the policy, consults the provider on its own worker thread, and
appends a `DecisionRecord` to `<data>/supervisor/shadow-<epoch>.supervisor.jsonl`.
Records outside an active run are skipped (counted in
`SupervisorStatus::skippedInactive`). Operator actions can be associated with
the latest recommendation through `SupervisorService::recordOperatorAction`.

Replaying a record offline:

```bash
python3 - <<'PY'
import json
for line in open("data/supervisor/shadow-1758326400.supervisor.jsonl"):
    r = json.loads(line)
    if "supervisor_log" in r: continue
    print(r["sequence"], r["decided_by"], r["recommendation"]["next_action"],
          r["provider"]["error"]["kind"], r["executed"])
PY
```

Each record's `snapshot` is the exact provider input; feed it back through
`decideOnce()` (or wrap it as a fixture) to reproduce the decision.

## Guarantees to keep in mind

- The service holds no camera, trigger, recording or hardware reference. A
  recommendation is data; `executed` is always `false` in shadow mode.
- The deterministic policy runs first and cannot be overridden; a provider
  error, timeout or cancellation fails closed to `HUMAN_REVIEW`.
- Provider calls run on the supervisor worker only; stop/finalize/shutdown
  never wait on one (`integration.e2e_supervisor_shadow` proves this with a
  provider that hangs for its full timeout).
- Model confidence is recorded, not trusted.
